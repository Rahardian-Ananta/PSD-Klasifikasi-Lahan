## 0.2 Aturan keras (berlaku di semua tahap)

1. **JANGAN mengarang angka.** Semua angka (jumlah pixel, polygon, statistik, FID, nilai band, metrik, luas) HARUS dihitung dari file saya. Tulis hasil dengan f-string dari variabel hasil perhitungan, bukan hardcode.
2. Jika angka tidak bisa diperoleh dari data, tulis: **"data tidak tersedia"**. Jangan menebak.
3. Yang **BOLEH** hardcode hanya konfigurasi/keputusan eksperimen (`RANDOM_STATE = 42`, `TEST_SIZE = 0.20`, `N_PER_CLASS = 50`, `MAX_PIXELS_PER_POLYGON = 500`, nama kelas, path file). Jumlah polygon/pixel/train/test, statistik, metrik, confusion matrix, dan distribusi kelas **tidak boleh** hardcode.
4. Jangan menulis "misalnya X = 100" bila X bisa dihitung. Jangan mengarang FID; jika FID yang diminta tidak ada, katakan tidak tersedia lalu pilih FID yang benar-benar ada.
5. Jangan mengarang kode/nomor kelas SNI atau KLHK. Verifikasi dari sumber resmi lewat web search (mencari dokumentasi referensi **bukan** "download data baru"). Jika tidak terverifikasi, tulis **"tidak terverifikasi"**.
6. **JANGAN download data baru**, jangan mencari training data baru, jangan membuat dataset baru. Subsampling dari data yang sudah ada (50 per kelas, learning curve) diperbolehkan.
7. **JANGAN bias** terhadap pixel-based maupun polygon-mean, dan jangan bias terhadap algoritma tertentu (RF, ExtraTrees, boosting, SVM). Keduanya eksperimen setara. Jangan menyatakan salah satu lebih baik sebelum ada hasil evaluasi.
8. **JANGAN data leakage.** Split WAJIB per polygon (FID), tidak boleh random per pixel. Tuning hanya lewat GroupKFold (group = FID) pada training. Test set dipakai SEKALI di akhir.
9. Jangan membuang polygon/pixel tanpa mencatat **alasan dan jumlahnya** (sebelum / dibuang / alasan / sesudah). Jangan mengubah label tanpa alasan dan laporan.
10. Jangan membuat pseudo-label dari model. Jangan memakai KMeans sebagai ground truth.
11. Jangan mengasumsikan nama kolom; periksa nama kolom aktual dulu.
12. Beri penanda eksplisit dan konsisten:
    - **DATA AKTUAL PROJECT** untuk hasil dari data;
    - **CONTOH ILUSTRASI — bukan data project** untuk angka kecil buatan (penjelasan RF, split, confusion matrix, formula).
    Jangan pernah mencampur keduanya, dan jangan menyebut contoh ilustrasi sebagai data aktual.
13. Bahasa ilmiah yang hati-hati: "cenderung membantu membedakan…", bukan "pasti". Tidak ada klaim kausal.
14. Raster besar: baca/proses **per window/blok**; jangan memuat seluruh raster sekaligus bila besar.
15. Jangan menjalankan eksperimen yang terlalu berat; sesuaikan dengan kapasitas komputer dan dokumentasikan bila ada kombinasi yang dilewati beserta alasannya.

## 0.4 Konteks provenance training data (WAJIB didokumentasikan jujur, di Bab 2)

Training sample **saya bentuk sendiri** dari sumber sekunder memakai script Python saya, **bukan** hasil survei lapangan. Parameter berikut hanya untuk **DOKUMENTASI**; JANGAN menjalankan ulang pengunduhan:

```python
RANDOM_STATE = 42
CRS_GEO = "EPSG:4326"
CRS_METRIC = "EPSG:32749"

SAWAH_URL    = "https://sig02.pertanian.go.id/server/rest/services/Sawah/LBS2019/MapServer/22"
BIG_BASE     = "https://kspservices.big.go.id/satupeta/rest/services/PUBLIK/SUMBER_DAYA_ALAM_DAN_LINGKUNGAN/MapServer"
LANDUSE_URL  = f"{BIG_BASE}/5"
MANGROVE_URL = f"{BIG_BASE}/57"
OCEAN_URLS   = ["https://naciscdn.org/naturalearth/10m/physical/ne_10m_ocean.zip",
                "https://naturalearth.s3.amazonaws.com/10m_physical/ne_10m_ocean.zip"]
OVERPASS_URLS = ["https://overpass-api.de/api/interpreter",
                 "https://overpass.kumi.systems/api/interpreter"]

# inner_buffer (m): polygon dikecilkan dari tepi agar piksel 10 m Sentinel-2 tidak mixed
# min_area (m2): luas minimum SETELAH inner buffer
CLASS_CFG = {
    1: dict(name="Sawah",                 inner_buffer=10, min_area=2000),
    2: dict(name="Bangunan / Permukiman", inner_buffer=15, min_area=5000),
    3: dict(name="Mangrove",              inner_buffer=10, min_area=2000),
    4: dict(name="Lahan hijau",           inner_buffer=15, min_area=5000),
    5: dict(name="Laut",                  inner_buffer=0,  min_area=250000),
    6: dict(name="Danau",                 inner_buffer=20, min_area=2000),
}
SEA_BUFFER_M = 25000          # area studi laut: 25 km dari batas Jatim
SEA_INNER_BUFFER_M = 3000     # jauhkan dari garis pantai NE 10m (akurasi kasar -> mixed pixel)
SEA_COAST_EXCLUSION_M = 2000  # buang zona di sekitar batas daratan Jatim
SEA_TILE_M = 3000             # pecah laut menjadi sel grid agar bisa disampling
CONFLICT_OVERLAP_FRAC = 0.05  # buang polygon yang >5% luasnya tumpang tindih dgn kelas lain
OVERSAMPLE = 3                # ambil kandidat n*3, filter konflik, lalu sampling final n
LAKE_MIN_TARGET = 50          # jika Danau dari BIG < ini -> tambah sumber OSM
INCLUDE_WADUK = True          # waduk dimasukkan ke Danau (dicatat di source_class)
```

| Kelas | Sumber |
|---|---|
| Sawah | Kementan, layer LBS2019 (sig02.pertanian.go.id, MapServer/22) |
| Bangunan/Permukiman, Lahan hijau, Danau, Mangrove | BIG Satupeta (layer penggunaan lahan /5 dan mangrove /57) |
| Laut | Natural Earth `ne_10m_ocean` |
| Danau/Waduk tambahan | OpenStreetMap (Overpass), hanya bila jumlah dari BIG < `LAKE_MIN_TARGET` |

**Tugas provenance:**

- Jelaskan fungsi tiap parameter (inner buffer, min_area, filter konflik, oversample, exclusion pantai laut).
- Periksa kolom provenance (mis. `source`, `source_class`) di file. Jika ada, tabulasikan per kelas; jika tidak, tulis "tidak tersedia".
- Tulis **secara jujur** keterbatasan label turunan sumber sekunder:
  - beda tahun (mis. LBS2019 vs citra 2025) sehingga tutupan bisa sudah berubah;
  - **musim dan rentang waktu citra:** citra hanya mencakup beberapa hari di awal September 2025; bahas dengan hati-hati bahwa kondisi tutupan (terutama sawah yang bisa bera/panen/tergenang) pada satu snapshot dapat berbeda dari kondisi label — tanpa mengklaim kondisi lapangan yang tidak ada di data;
  - skala dan akurasi posisi sumber (mis. Natural Earth 10m untuk garis pantai);
  - kemungkinan label noise;
  - mixed pixel di tepi polygon, serta peran inner buffer dan filter konflik;
  - kelas "Lahan hijau" yang luas dan ambigu;
  - sebagian polygon tidak valid (diukur di Bab 2, **jangan menebak penyebabnya**).
- Tegaskan: label ini **bukan pseudo-label hasil model** dan **bukan ground truth lapangan**. Metrik mengukur **kesesuaian dengan label sumber ini**, bukan akurasi terhadap kondisi lapangan.

## 0.6 Definisi "polygon valid" dan batas 50 per kelas

**Semua polygon di file mentah diperiksa; tidak semua valid.** Terapkan saringan berikut, berurutan, pada SEMUA polygon, dan catat jumlah dibuang **per kelas dan per alasan**:

| Kode | Kriteria polygon dianggap valid |
|---|---|
| V1 | Geometri tidak null/kosong; FID unik (tidak duplikat) |
| V2 | Tipe `Polygon` atau `MultiPolygon` |
| V3 | `geometry.is_valid == True` pada geometri **asli**. **Jangan diperbaiki** dengan `make_valid`/`buffer(0)`; yang invalid dikeluarkan. Catat `explain_validity` untuk tiap alasan. |
| V4 | Label lengkap dan konsisten: `class_id` ∈ {1..6}, `class_name` cocok dengan pemetaan 0.3 |
| V5 | Berpotongan dengan extent raster **dan** menghasilkan ≥ `MIN_VALID_PIXELS` pixel valid (bukan nodata, nilai band tidak NaN/inf), `MIN_VALID_PIXELS = 1` (konfigurasi; boleh dinaikkan, laporkan dampaknya) |
| V6 | Tidak tumpang tindih lintas kelas melebihi `CONFLICT_OVERLAP_FRAC` (0.05) dari luasnya |

**Pemilihan 50 per kelas:**

- Dari pool polygon valid tiap kelas, ambil **acak reproducible** `N_PER_CLASS = 50` dengan `random_state = 42`. Jangan memilih berdasarkan luas, tampilan, atau performa model.
- Jika suatu kelas punya < 50 polygon valid: pakai semua yang valid, **laporkan dengan jelas**, jangan diisi dengan polygon invalid atau data baru.
- Pisahkan dua jenis pengecualian dalam catatan: (a) **tidak valid** (beserta kode V1–V6) dan (b) **valid tetapi tidak terpilih karena kuota**.
- Simpan: `polygon_selected` (300 polygon bila semua kelas ≥ 50) dan `polygon_excluded.csv` (FID, class_id, class_name, kategori, kode/alasan).
- Seluruh tahap sesudah pemilihan (split, ekstraksi, training, evaluasi) memakai **hanya polygon terpilih**.
- Karena data kecil, **akui keterbatasannya**: dengan 10 polygon test per kelas (bila tercapai), satu polygon salah mengubah recall kelas tersebut sebesar 10 poin persen. Selisih kecil antar model tidak boleh diklaim bermakna; laporkan std antar fold CV dan selang ketidakpastian (mis. bootstrap per polygon pada test) sebagai **informasi**, bukan dasar pemilihan model.

## 0.7 Aturan seleksi pixel dan capping

- Pixel dari polygon: aturan default **centroid pixel berada di dalam polygon** (`all_touched=False`). Bandingkan dengan `all_touched=True` pada contoh FID di Bab 2 dan jelaskan dampaknya pada mixed pixel. Pilihan final harus konsisten di seluruh pipeline dan dicatat di metadata model.
- **Capping:** maksimal `MAX_PIXELS_PER_POLYGON = 500` pixel valid per polygon untuk **dataset pixel-based**. Polygon dengan > 500 pixel valid di-sampling acak reproducible (`random_state = 42`); yang ≤ 500 dipakai seluruhnya. Catat jumlah sebelum dan sesudah. Capping tidak mengubah data asli.
- **Polygon-mean** dihitung dari **semua pixel valid** polygon (tanpa cap, karena mean tidak membutuhkannya). Dokumentasikan keputusan ini dan konsisten.
- Indeks pada polygon-mean: pilih satu definisi (indeks dihitung dari mean band **atau** mean dari indeks pixel), jelaskan alasannya, dan pakai konsisten di seluruh pipeline.
- Nodata dan pembagi nol pada indeks: jelaskan penanganannya dan catat jumlah pixel yang terdampak.

## 0.9 Format dan eksekusi notebook

1. Format **`.ipynb`**, bukan `.py`. Jangan membuat satu notebook raksasa, diperbolehkan menggunakan aturan bab dan sub bab.
```
# Table of contents
# Learn more at https://jupyterbook.org/customize/toc.html

format: jb-book
root: intro
parts:
  - caption: BAB 1 — [JUDUL BAB 1]
    chapters:
      - file: folder_bab1/nama_file_1
        title: 1.1 [Judul Sub-bab]

  - caption: BAB 2 — [JUDUL BAB 2]
    chapters:
      - file: folder_bab2/nama_file_1
        title: 2.1 [Judul Sub-bab]
        sections:
          - file: folder_bab2/nama_file_sub_1
            title: 2.1a [Judul Section]
```
2. Pola tiap bagian: **penjelasan konsep → pertanyaan yang dijawab → code → output aktual → interpretasi** (markdown cell berisi apa yang terlihat dan implikasinya, hanya dari output aktual). Pisahkan menjadi banyak cell logis; jangan satu `print()` raksasa.
3. **Notebook WAJIB dijalankan:** buat → jalankan (`nbconvert --execute` atau setara) → pastikan semua cell sukses dan output muncul → perbaiki error → jalankan ulang → simpan **dalam kondisi ter-eksekusi**. Tidak boleh ada `In [ ]:` pada cell penting. Notebook yang belum dieksekusi dianggap **belum selesai**.
4. Kompatibel Jupyter Book: periksa `_config.yml` dan `_toc.yml` yang sudah ada, lalu tambahkan notebook. Raster besar **tidak** dieksekusi saat build Jupyter Book: gunakan `execute_notebooks: off` dengan notebook yang sudah ter-eksekusi (output tersimpan), atau `cache`.
5. Prinsip kerja: **BUAT KODE → JALANKAN → PERIKSA OUTPUT → INTERPRETASIKAN**, bukan menulis output lalu membuat kode seolah-olah output itu benar.
